# Further 实施计划

> 状态：实施中；阶段 0 至阶段 5 已完成并提交

## 目的

本文把首版实现拆成可独立验收和提交的 Coding 阶段。实施顺序优先保证领域语义、数据可靠性与核心循环，不以页面数量或快速堆叠功能衡量进度。

每个阶段只实施当前范围。后续阶段可见不表示可以提前实现；确需调整顺序时，先说明依赖变化及其影响并更新本文。

## 阶段 0：工程骨架

> 状态：已完成并提交

### 范围

- 建立技术架构约定的目录结构。
- 配置 String Catalog。
- 增加 UI 测试 target。
- 建立 App 组合入口与测试数据入口。
- 保持现有启动页面正常运行。

### 验收

- 模拟器构建、单元测试和 UI 测试通过。
- Swift 6 严格并发检查没有警告。
- 没有引入第三方依赖。
- 尚未建立业务领域模型或接入系统能力。

### 学习重点

Xcode target、Swift module、App 生命周期、组合入口，以及单元测试与 UI 测试的职责差异。

## 阶段 1：纯领域模型

> 状态：已完成并提交

### 范围

- 活动、作品、表达、暂停事件和路线样本等值类型。
- 作品生命周期与完成规则。
- 时间和里程碑边界。
- 版本化共享活动数据契约。
- 可控时间源 seam。

### 验收

- 领域代码不依赖 SwiftUI、SwiftData 或系统权限。
- 跨时间边界、技术中断、里程碑和距离缺失测试通过。
- 数据契约编码往返后语义不变。

### 学习重点

Swift `struct`、`enum`、值语义、protocol、`Codable` 和单元测试。

## 阶段 2：SwiftData 与 FurtherStore

> 状态：已完成并提交

### 范围

- SwiftData V1 schema 与迁移计划。
- 内部持久化模型和领域快照映射。
- `FurtherStore` 高层 interface。
- 当前作品唯一性和原子状态变化。
- `AppBootstrap`。

### 验收

- 数据在 App 重启后保持一致。
- 内存容器集成测试通过。
- 遗留进行中会话形成技术中断记录。
- 遗留收束草稿直接锁定。
- 数据库无法打开时不会静默创建替代数据库。

### 学习重点

SwiftData、`ModelContainer`、actor 隔离，以及领域类型与数据库模型的差异。

## 阶段 3：作品周期与主空间

> 状态：已完成并提交

### 范围

- 首次作品周期选择。
- 空白、积累中和已完成三种作品状态。
- 简单、确定性、可替换的基础作品表现。
- 根级类型安全导航。

### 验收

- 首次启动可以建立唯一作品。
- 空白作品没有虚构印记。
- 时间作品在第一条跑步之前不开始计时。
- 重启后进入正确作品状态。

### 学习重点

SwiftUI 状态流、Observation、`NavigationStack` 和依赖注入。

## 阶段 4：RunRecorder 与室内跑步

> 状态：已完成并提交

### 范围

- 倒数、运动中、暂停、继续和结束。
- 基于时间点计算活动时间。
- 进行中会话检查点。
- 不依赖定位的室内跑步路径。

### 验收

- 用户最终确认开始后必定形成活动。
- 暂停期间活动时间不增加。
- 取消结束确认后恢复此前状态。
- App 进入后台再返回时，界面计时与事实时间一致。

### 学习重点

Swift Concurrency、actor、异步状态流和基于时间点的计时。

## 阶段 5：收束与记录进入作品

> 状态：已完成并提交

### 范围

- 默认沉默记录。
- 感受色、短记和保持沉默。
- 室内手动距离。
- 表达锁定。
- 记录进入作品的基础反馈。

### 验收

- 四种合法表达组合均能成立。
- 最终表达锁定后不能修改。
- 跳过室内距离后保持未知。
- 收束期间 App 被系统终止后不形成待办。
- 新记录能够真实改变当前作品。

### 学习重点

输入状态、持久化时机、原子变化和 SwiftUI 转场。

阶段 5 完成后，Further 的第一个完整核心循环成立。

## 阶段 6：室外跑步与路线

### 范围

- 定位按需授权。
- Core Location adapter。
- 位置质量过滤和距离累计。
- 路线批量持久化。
- 后台定位能力。
- 单次记录路线展示。

### 验收

- 拒绝定位仍可完成跑步。
- 未知距离不会显示为零。
- 锁屏和后台追踪通过真机验证。
- 短暂定位缺口不形成技术中断。
- 长时间路线保存没有明显阻塞或数据丢失。

### 学习重点

Delegate 封装、`AsyncSequence`、Core Location 权限和后台执行。

## 阶段 7：回望与单次记录

### 范围

- 按年月分组的回望。
- 感受、短记和弱化的客观事实。
- 正常结束与技术中断详情。
- 路线存在与缺失状态。

### 验收

- 所有正式记录均可找到。
- 按跑步开始地的当地日期正确分组。
- 缺失短记、距离或路线不会阻止详情展示。
- 不出现编辑和删除入口。

### 学习重点

SwiftData 查询快照、列表性能和日期本地化。

## 阶段 8：作品完成与作品集

### 范围

- 时间作品到期。
- 里程碑完成。
- 完成作品停留。
- 开启下一幅作品。
- 旧作品归集。

### 验收

- 技术中断正常参与作品但不能完成里程碑。
- 新旧作品切换保持原子性。
- 不会出现两幅当前作品。
- 已完成作品不因 App 更新改变生成结果。

### 学习重点

跨实体事务、确定性生成和生命周期不变量。

## 阶段 9：HealthKit 与设置

### 范围

- HealthKit capability。
- `HealthExporter`。
- Workout、暂停事件、距离和路线写入。
- 幂等与静默重试。
- 单位和权限设置。

### 验收

- 拒绝授权不影响核心流程。
- 重试不产生重复 workout。
- 正常结束和技术中断都能写入可靠事实。
- HealthKit 写入通过真机验证。

### 学习重点

HealthKit 数据模型、系统授权、外部写入和幂等。

## 每个阶段的完成规则

每个阶段都必须满足：

1. 变更只覆盖当前阶段和必要的直接依赖。
2. 工程构建通过，相关自动化测试通过。
3. 新增关键规则具有自动化测试。
4. 需要真机验证时，提供明确步骤和预期结果。
5. 交付说明指出最值得阅读的入口文件和状态流。
6. 提交前展示变更与验证结果，并等待用户确认。
7. 一个阶段对应一个主要 Git commit，不使用 GitHub Issues 管理个人项目进度。

## Coding 起点

首个 Coding 任务只实施阶段 0“工程骨架”。完成并验收阶段 0 后，才能开始阶段 1 的领域模型。
