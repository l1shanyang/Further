# Further 数据模型与系统边界

> 状态：已确认

## 文档目的

本文定义 Further 首版的逻辑数据模型、数据生命周期和系统权威。它约束未来代码必须保存什么、不同事实由谁负责，以及外部系统与本地记录如何关联，但不指定 SwiftData 模型类、服务分层、文件结构或序列化实现。

## 核心关系

```text
作品
  └── 共享活动记录
        ├── 跑步会话事实
        ├── 暂停与继续事件
        ├── 路线样本
        ├── 表达结果
        ├── 生命周期结果
        └── 外部写入状态

共享活动记录
  └── 在 Further 中成为记录点
        └── 生成印记并参与所属作品
```

一次跑步只建立一条共享活动记录。“记录点”是这条记录在 Further 中的完整产品含义，不复制另一份活动事实。印记是记录点在作品中的视觉表现，同样不成为第二份客观活动数据。

## 共享活动记录

共享活动记录是一次跑步的规范化数据聚合，至少承载：

- 产品矩阵范围内稳定的全局活动 ID
- 数据契约版本与创建来源
- 跑步环境
- 会话生命周期
- 客观时间、距离与路线事实
- 暂停和继续事件
- 最终表达
- 所属作品
- 数据来源、质量与派生版本
- HealthKit 等外部系统的关联与写入状态

全局活动 ID 在用户正式确认开始时建立，之后保持稳定。HealthKit UUID、数据库内部标识和设备标识都不能取代它。

每条活动只属于一幅作品。作品归属在正式开始时确定，之后不能迁移到其他作品。

## 会话生命周期

### 正式开始前

进入准备跑步或选择室内、室外环境时不创建活动记录。用户执行最终开始操作后，立即建立活动 ID 和可持久化的进行中会话；“开始即留下记录”从这一刻成立。

### 进行中

会话持续保存最后可靠检查点。暂停和继续作为有时间点的事件保存，不只保留一个最终累计时长。活动时间、暂停时间和自然持续时间必须能够从会话事实与事件中验证。

### 正常结束与收束

正常结束先固定客观会话事实，再建立默认沉默的收束草稿。收束草稿即时保存当前颜色、短记或沉默，但只是本次收束中的短暂状态，不是用户可见或可跨启动恢复的待办。

用户完成收束时，草稿转化为不可改写的最终表达。App 在收束期间被系统终止时，下次启动直接将最后可靠草稿转化为最终表达；不存在可靠主动表达时，保留已经成立的沉默结果。

### 技术中断

技术中断按最后可靠检查点结束会话，并直接形成沉默表达。它使用与正常结束完全相同的共享活动记录结构，是完整、正式且平等的记录点，不是异常附属数据。

技术中断与正常结束只通过生命周期语义区分。它正常参与作品、回望、备份和可靠客观事实的 HealthKit 写入，但不能完成里程碑。

### 不可删除与客观纠正

最终表达和作品归属不可改写，记录点不可删除。首版契约不设置删除状态或墓碑；未来如出现真实的同步删除需求，通过新的契约版本扩展，而不提前引入无效状态。

客观事实未来允许纠正，但必须保留原始值、修正值、修正来源和修正时间，不能静默覆盖原始事实。首版不提供执行这种纠正的界面。

## 作品

作品是独立的数据聚合，生命周期为：

```text
空白 → 积累中 → 已完成 → 已归集
```

- 同一时间最多存在一幅未归集作品，包括已经完成但仍停留在主空间的作品。
- 空白时间作品直到第一条活动正式开始时，才确定起始时间和结束边界。
- 每次正式开始跑步前重新检查时间边界，避免新活动进入已经到期的作品。
- 里程碑只能由正常结束且具有有效最终距离的活动完成。
- 技术中断记录仍正常进入所属作品，但不触发里程碑完成。
- 作品完成后不再接收活动；开启下一幅作品时，旧作品转为已归集。

每幅作品在创建时绑定视觉生成版本，使进行中作品和历史作品不会因 App 更新被无意改写。作品保存可重建视觉结果所需的生成版本、稳定种子和版本化参数；渲染图片可以作为缓存，但不能成为唯一事实来源。

具体构图、材质、笔触与视觉参数由后续美术阶段决定。逻辑模型只要求生成描述可版本化、可移植，并能够追溯到构成作品的真实记录。

## 时间、单位与缺失值

- 保存绝对起止时间，同时保存跑步开始地的时区标识。
- 时间持久化使用秒，距离持久化使用米；显示单位不回写基础事实。
- 未知使用明确的缺失语义，不用零、空字符串或默认对象代替。
- 摘要至少区分自然持续时间、活动时间、暂停时间、最终距离和距离来源。
- 配速由有效距离和活动时间派生，不作为独立权威事实；如需缓存，必须保留派生规则版本并能够重建。

距离来源至少能够区分：

- 基于室外位置样本派生
- 室内人工输入
- 未来外部设备或其他明确来源

室内人工距离是该次室内跑步最终距离的权威来源，永久保留人工输入标识。

## 路线与派生事实

室外路线保存带时间的位置测量，包括经纬度、海拔、水平精度和垂直精度。路线数据作为活动记录的独立子数据存在，不能压缩成页面字段或单个难以增量处理的文本对象。

位置样本保留其是否被距离算法采用，以及参与判断的规则版本。这样可以同时保留原始测量、质量过滤结果和最终派生距离的可追溯关系。

短暂缺口是时序事实的一部分，不自动形成技术中断，也不能通过最后速度猜测缺失路线或距离。

## 表达数据

最终表达明确区分有色表达和沉默：

- 感受色保存稳定颜色 ID、调色板版本和用户选择当时的具体颜色值。
- 沉默保存稳定颜色身份和生成规则版本，备份恢复后不能重新随机生成另一种颜色。
- 短记保存为纯文本，不支持富文本。
- 沉默可以附带短记，表达类型仍然是沉默。
- 作品使用的衍生颜色、透明度和纹理不能覆盖原始记录色。

具体颜色空间、文本长度与输入限制在技术规格阶段确定。

## 设置与系统元数据

距离显示单位等用户设置独立保存，不混入活动或作品数据。

HealthKit 写入状态、外部 UUID、重试信息和粗粒度技术中断原因属于系统元数据，不属于用户感受或作品内容。活动记录不包含崩溃日志、诊断文件或机器相关临时状态。

## 系统权威

### Further 本地数据

Further 本地数据是以下内容的唯一产品权威：

- 共享活动记录及其全局身份
- 最终表达
- 作品归属和作品生命周期
- 作品生成信息
- HealthKit 外部对象映射

本地记录的成立不依赖网络、HealthKit 或其他 App。

### Core Location

Core Location 是室外位置的测量来源。Further 负责保存规范化位置样本、记录质量判断，并依据版本化规则形成最终距离。Core Location 不拥有 Further 的活动身份、表达或作品关系。

### HealthKit

HealthKit 是单向外部副本和 Apple 生态交换层，不是 Further 首版的数据权威。

- 只有已经结束的活动可以写入 HealthKit。
- 正常结束和技术中断都可以写入其中可靠的客观事实。
- 没有权限、权限被撤销或写入失败不会改变本地记录。
- 成功写入后保存 HealthKit UUID，并使用产品全局活动 ID 保证重试幂等。
- 权限拒绝后停止自动尝试；临时失败保留静默重试状态，但不形成用户待办。
- 首版不从 HealthKit 反向导入、合并或修复 Further 记录。

## 产品矩阵与可移植性

首版不建立 App Group、共享数据库或产品矩阵实时共享层。未来跨产品能力建立在版本化共享活动契约上，而不是直接共享某个 App 的数据库表。

数据契约从首版开始拥有独立 schema 版本，并能够独立于本地数据库结构进行编码和迁移。即使完整备份界面后续实现，活动、路线、事件、表达、作品和外部映射也必须能够被完整序列化。

完整备份的封装格式、未来产品间传输机制和恢复冲突语义留到对应功能实施前决定。
