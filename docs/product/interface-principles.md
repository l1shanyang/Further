# Further 基础界面原则

> 状态：已确认

## 文档目的

本文定义 Further 在进入页面设计与代码实现前必须遵守的基础界面语言。它约束界面的气质、信息层级、导航、交互反馈和可访问性，但不提前确定调色板、作品构图、材质、笔触或动画参数。

Further 的界面应像一个安静的私人作品空间，而不是运动工具、训练面板或数据仪表盘。原生体验是实现品质的基础，但界面不能因此退化为系统设置页式的信息堆叠。

## 整体气质

- 平静、克制、清晰。视觉可以冷淡并保有距离感，但交互、文案和异常处理不能冷漠、含糊或忽视用户。
- 变化来自真实跑步记录进入作品，而不是提醒、激励口号或奖励机制。
- 极简服务于注意力集中，不以隐藏功能、牺牲可理解性为代价。
- 界面允许留白，并让作品承担主要的情绪表达。

## 视觉层级

首版采用以下稳定层级：

1. 当前作品
2. 当前页面唯一的主要行动
3. 感受色与短记
4. 日期、距离、活动时间等客观事实
5. 系统状态、权限与辅助信息

不同空间的信息密度应服从各自职责：

- 作品空间保持低密度，让作品成为视觉中心。
- 跑步空间清楚、稳定，确保运动中可以快速辨认和操作。
- 收束空间高度聚焦，只服务于当下表达。
- 回望保持适中的信息密度，便于寻找记忆但不形成数据报表。
- 设置采用朴素、直接的系统式结构。

不把所有内容包装成卡片。只有在内容确实具有独立边界或交互边界时才使用容器，避免通过重复圆角、阴影和层层嵌套制造视觉噪声。

## 字体与文字

- 首版使用 Apple 系统字体，不引入品牌字体。
- 正文和辅助信息保持轻声量；跑步中的计时与距离数字需要稳定、易读，并使用等宽数字避免跳动。
- 不使用全大写、感叹号堆叠、挑战式标题或激励口号制造紧迫感。
- 文案陈述事实，不评价用户是否努力、优秀、坚持或退步。
- 错误与异常文案只说明发生了什么、哪些内容已经保存，以及用户现在可以做什么，不归责于用户。

## 导航与操作

- 不使用底部标签栏；当前作品是唯一主空间。
- 每个页面只设置一个明确的主要行动，其他入口降低层级。
- 回望、作品集和设置等关键入口必须可见、可理解，不能只依赖滑动、长按等隐藏手势。
- 隐藏手势只能作为已存在操作的补充，不能承载唯一能力。
- 权限、设置、文字输入、确认、返回和无障碍行为优先采用原生交互习惯。
- 作品呈现与感受色选择可以建立 Further 自身的交互语言，但不能削弱基本可用性。
- 跑步和收束是专注流程，不在其中插入统计报告、作品集入口或 HealthKit 状态等无关信息。

## 动效与触感

动效只用于表达明确的状态变化：

- 开始、暂停、继续和结束跑步
- 本次记录进入当前作品
- 当前作品完成
- 主要空间之间的进入与返回

动效应平静但可感知。首版不使用循环装饰动画、庆祝粒子、徽章弹出或类似游戏奖励的表现。持续时间、缓动、轨迹和作品生成动画留到交互与美术设计阶段确定。

触感反馈只用于需要确认感的动作，例如开始、暂停、继续、确认结束和完成表达，不为普通浏览操作增加触感。

所有关键状态变化必须支持“减弱动态效果”。关闭或减弱动画后，状态含义仍然完整，流程仍然可操作。

## 明暗模式与颜色职责

- 界面框架跟随系统浅色或深色模式。
- 历史记录的原始感受色不能因为界面模式改变而被重新解释或替换。
- 作品画布在不同模式下的具体处理留到美术阶段确定，但必须保持记录表达的连续性。
- 感受本身可以主要由颜色表达，因为颜色就是用户主动选择的内容。
- 系统状态不能只依赖颜色。暂停、权限、技术中断、选中状态和确认结果还需要文字、形状、布局或其他结构性提示。

## 可访问性与运动场景

- 支持 Dynamic Type，文字放大后不能遮挡关键事实或主要行动。
- 支持 VoiceOver；感受色使用中性的可识别名称或编号，不由系统擅自赋予“积极”“消极”等情绪标签。
- 跑步中的主要操作使用足够大的触控区域，适合运动状态和单手操作。
- 计时、距离、暂停状态与结束操作在运动过程中保持高辨识度，不因追求留白而变得模糊。

## 首版实现边界

首版可以使用简单、可替换的作品表现来承载产品逻辑，但必须真实证明以下过程：

1. 一次跑步记录进入当前作品。
2. 多次记录在同一作品中持续积累。
3. 作品抵达边界并完成。
4. 完成作品在开启下一周期后进入作品集。

这个基础表现不能冒充最终美术方案。调色板、画布、构图、材质、笔触和高级生成方式仍由后续独立的美术设计阶段决定。

界面设计与实现按以下顺序保证品质：

1. 当前作品空间
2. 结束与收束体验
3. 跑步追踪空间
4. 回望与单次记录
5. 作品集
6. 设置

该顺序表示设计注意力与验收优先级，不改变完整首版范围，也不要求按照页面顺序机械开发。
